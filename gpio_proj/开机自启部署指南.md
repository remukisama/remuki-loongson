# GPIO 看门狗开机自启部署指南

> 适用：龙邱 LS2K0301 龙丘核心板 | gpio_manager 守护进程

---

## 一、部署前准备

在开发主机（本机）编译好二进制：

```bash
cd /home/pi/桌面/gpio_proj
./build.sh manager
```

编译产物：`build/gpio_manager`

---

## 二、传输到开发板

```bash
# 替换 <板子IP> 为实际地址，下同
scp -O build/gpio_manager root@<板子IP>:~/
scp -O gpio-manager.service root@<板子IP>:~/
```

---

## 三、板子上安装服务

```bash
# SSH 登录板子
ssh root@<板子IP>

# 1. 放置二进制
cp ~/gpio_manager /root/
chmod +x /root/gpio_manager

# 2. 安装 systemd 服务文件
cp ~/gpio-manager.service /etc/systemd/system/

# 3. 重载 systemd 配置
systemctl daemon-reload

# 4. 启动服务
systemctl start gpio-manager

# 5. 设为开机自启
systemctl enable gpio-manager
```

---

## 四、验证

```bash
# 查看运行状态（应显示 active (running)）
systemctl status gpio-manager

# 查看实时日志
journalctl -u gpio-manager -f

# 确认进程存在
ps aux | grep gpio_manager
```

预期输出：

```
● gpio-manager.service - GPIO Watchdog Daemon
     Loaded: loaded (/etc/systemd/system/gpio-manager.service; enabled)
     Active: active (running) since ...
   Main PID: xxxx (gpio_manager)
```

## 五、服务文件说明

文件位置：`/etc/systemd/system/gpio-manager.service`

```ini
[Unit]
Description=GPIO Watchdog Daemon — motor safety watchdog for Loongson 2K301
After=network.target
Before=car-project.service          # 确保在小车工程之前启动

[Service]
Type=simple
ExecStart=/root/gpio_manager
CPUSchedulingPolicy=fifo            # 实时调度策略（FIFO）
CPUSchedulingPriority=90            # 实时优先级（1~99，越高越优先）
Restart=always                      # 崩溃后自动重启
RestartSec=1                        # 重启间隔 1 秒
StandardOutput=journal              # 日志输出到 journal
StandardError=journal

[Install]
WantedBy=multi-user.target          # 多用户模式下自动启动
```

### 关键参数解释

| 参数 | 值 | 说明 |
|------|-----|------|
| `CPUSchedulingPolicy` | `fifo` | 实时调度，不被普通进程抢占 |
| `CPUSchedulingPriority` | `90` | 高优先级，确保看门狗按时检测心跳 |
| `Restart` | `always` | 看门狗自身崩溃也会自动重启 |
| `Before` | `car-project.service` | 保证看门狗先于小车工程启动 |

## 六、常用管理命令

```bash
# 服务管理
systemctl start gpio-manager        # 启动
systemctl stop gpio-manager         # 停止
systemctl restart gpio-manager      # 重启
systemctl status gpio-manager       # 查看状态

# 开机自启管理
systemctl enable gpio-manager       # 启用开机自启
systemctl disable gpio-manager      # 禁用开机自启

# 日志查看
journalctl -u gpio-manager -f       # 实时跟踪日志
journalctl -u gpio-manager -n 50    # 查看最近 50 条
journalctl -u gpio-manager --since today  # 今天的日志
```

## 七、与小车工程的配合

### 启动顺序

系统开机后，gpio-manager 自动启动（`WantedBy=multi-user.target`）。
小车工程应作为单独的 systemd 服务启动，服务文件中添加依赖：

```ini
# car-project.service 示例
[Unit]
Description=Car Control Project
After=gpio-manager.service          # 在看门狗之后启动
Requires=gpio-manager.service       # 强依赖：看门狗未运行则小车工程也不启动

[Service]
Type=simple
ExecStart=/root/car_project
Restart=always
RestartSec=1

[Install]
WantedBy=multi-user.target
```

### 停止顺序

停止时应先停小车工程，再停看门狗：

```bash
systemctl stop car-project          # 先停小车
systemctl stop gpio-manager         # 再停看门狗
```

如果直接停看门狗，小车线程仍在运行，但失去安全保护。小车线程后续被停止时，电机引脚不会自动恢复安全值（因为看门狗已不在）。

## 八、调试场景

### 开发调试时临时关闭看门狗

```bash
systemctl stop gpio-manager         # 停止看门狗
# ... 调试小车工程 ...
systemctl start gpio-manager        # 调试完重新启动
```

### 替换新版 gpio_manager

```bash
# 开发主机上编译
./build.sh manager

# 传输到板子
scp -O build/gpio_manager root@<板子IP>:~/gpio_manager

# 板子上替换并重启
ssh root@<板子IP>
systemctl stop gpio-manager
cp ~/gpio_manager /root/gpio_manager
chmod +x /root/gpio_manager
systemctl start gpio-manager
```

### 查看看门狗是否进入过安全模式

```bash
journalctl -u gpio-manager | grep "Safe values"
```

如果看到 `Heartbeat lost! Safe values written`，说明小车线程曾经异常掉线，看门狗已接管。

## 九、安全值修改

方向 GPIO 的安全电平需要实际测量车架确定。修改位置：

```
gpio_proj/config/board_2k301.hpp
```

```cpp
#define SAFE_MOTOR_DIR          0           // 0=LOW, 1=HIGH（根据车架实测）
```

修改后重新编译部署：

```bash
./build.sh manager
# 传输并重启服务（见第七节"替换新版"）
```
