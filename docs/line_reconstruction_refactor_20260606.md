# 巡线与补线重构说明 2026-06-06

## 目标

当前底盘已经基本稳定，主要风险从控制环转到视觉中线质量：单侧丢边、宽度异常、补线斜率跳变时，中线会突然飘到错误位置。此次重构只改视觉中线裁决层，保留原有扫线、元素判断、TFT/UDP显示和 T03/T06/T08/T13/T14 调参入口。

## 采用的算法思路

1. 边界可信度评分
   - 每行先判断左右边界是否真实找到，再检查赛道宽度是否落在合理范围。
   - `T/H` 边界优先可信，`W` 和宽度偏离过大的边界降权。

2. 单侧可靠边界补线
   - 一侧丢线但另一侧可靠时，不再用旧边界简单平均。
   - 使用该行标定半宽 `Half_Road_Wide[row]` 从可靠边界反推中心。

3. 行间连续性约束
   - 每行中心相对下一行最多移动 `kCurveCenterMaxRowStep`。
   - 这相当于轻量级车道模型约束，防止远端中心突然横跳。

4. 跨帧预测限速
   - 同一行中心相对上一帧最多接纳 `kCurveCenterFrameMaxStep`。
   - 当双边都弱或宽度异常时，使用更小的 `kCurveCenterBadFrameMaxStep`。
   - 这是嵌入式版的时序跟踪思想，不引入完整 Kalman 矩阵，实时开销极低。

## 为什么没有直接上重型方案

Hough/RANSAC/Kalman/IPM 在标准车道线检测里很常见，但本项目当前输入已经被压缩到 80x60，且目标是高速闭环巡线。直接上完整 Hough 或 RANSAC 会增加 CPU 和调参成本，还可能与现有元素补线状态机冲突。本次先把这些方法中最有用的部分落到现有架构里：离群点抑制、几何模型约束、历史跟踪。

## 关键参数

- `kCurveCenterCompEnable`: 总开关。T14 显示方向错误时可置 `false` 快速回退。
- `kCurveCenterWidthTolerance`: 宽度偏离门槛。中线仍跳边时可减小，漏补线时可增大。
- `kCurveCenterMaxRowStep`: 行间最大步长。中线锯齿大则减小，急弯跟不上则增大。
- `kCurveCenterFrameMaxStep`: 跨帧正常限速。中线抖则减小，S 弯滞后则增大。
- `kCurveCenterBadFrameMaxStep`: 弱观测限速。坏图像带飞控制时优先减小。

## 建议验证顺序

1. `T14` 手推补线 TFT 观察：先不开电机，看红色中线是否连续、居中、不过度贴单侧。
2. `T13` 手推正常路径基准：确认 near/mid 边界覆盖、安全余量没有恶化。
3. `T06` 低速视觉+陀螺闭环：看 `img_bad/img_warn/large_offset` 是否下降。
4. `T08H/T08` 元素补线：确认圆环阶段的中心线方向没有被普通补线抢走。

## 风险信号

- T14 中线明显滞后于弯道：先把 `kCurveCenterFrameMaxStep` 从 4 增到 5。
- T14 中线仍会单帧横跳：先把 `kCurveCenterBadFrameMaxStep` 从 2 降到 1。
- 普通弯正常但圆环不进/不出：先不要调普通补线，去 T08H 看元素状态和环岛偏置。
- T13 安全余量变差：回查 `kImageMiddleLine`、摄像头安装、ROI，而不是先加 PID。
